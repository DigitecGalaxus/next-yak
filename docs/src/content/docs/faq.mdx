## General questions

### Is yak production ready?

Yes, yak is production ready and used in production at scale.

[Digitec Galaxus](https://www.galaxus.ch), Switzerland's largest e-commerce platform, sponsors yak and uses it in production with thousands of styled components across more than 100 engineers. They saw significant improvements in Core Web Vitals performance: over 20% faster LCP, 15% reduced SSR latency, and 10% faster INP, especially on mobile devices. You can read more about the journey in the [blog post](https://www.galaxus.ch/page/next-yak-innovation-made-in-zuerich-teil-2-37910).

### What frameworks and bundlers does yak support?

yak supports React and Solid, and the same SWC plugin runs in every bundler below:

- **[Next.js](/docs/getting-started)** 16.4+ with both **webpack** and **Turbopack**, for the App Router and the Pages Router
- **[Vite](/docs/vite)** 7+, including Vite 8 with OXC/Rolldown. Vite-based frameworks like React Router and TanStack Start (also with React Server Components) work too
- **[Rsbuild](/docs/rsbuild)** 2+ through `@yak/react/rsbuild`, which also covers Rsbuild-based TanStack Start
- **Solid** 2 with Vite through the `@yak/solid` package
- **[Storybook](/docs/storybook)** 10+ with both the Vite and the webpack builder through the `@yak/storybook` addon

The [Examples](/docs/examples) page has a runnable project for most of these setups. If you need yak in a framework that isn't on this list, ask for it in our [GitHub issue tracker](https://github.com/DigitecGalaxus/next-yak/issues) and we'll give it a thought.

### Can I mix/combine yak with other CSS-in-JS libraries?

Yes, you can use yak with other CSS-in-JS libraries.

You can use it with styled-components, emotion, tailwind or any other library that adds css classes to your components.

```tsx title="my-component.tsx"
import { styled, atoms } from "@yak/react";

const Button = styled.button`
  background: #bf4f74;
  /* Target classes from other libraries */
  & .my-class-from-another-library {
    color: white;
  }
  /* use tailwind classes */
  ${atoms("mx-auto flex max-w-7xl items-center justify-between p-6 lg:px-8")}
`;
```

<Callout type="info">
  If you used the older `:global()` syntax, remove the wrapper and keep the selector. A `:global()`
  selector is a build error in `@yak/react`.
</Callout>

### Can I reference a component in another component?

Yes, you can reference it in the tagged template literal the same way you would to it with styled-components.

```jsx title="my-component.tsx"
import { styled } from "@yak/react";

const Button = styled.button`
  background: #bf4f74;
`;

const Nav = styled.nav`
  background: #bf4f74;
  ${Button} {
    color: white;
  }
`;
```

### Why does yak always generate CSS variables when the values are static references that are known at build time?

It's very hard to determine statically if a value is static or dynamic. We decided to always generate CSS variables to be on the safe side
and add errors if we detect that a value is static but a CSS variable is used.

### Can I use yak with TypeScript?

Yes, yak is fully type safe.

### Can I contribute to yak?

Yes.

We are happy about every contribution. Just write an issue or a pull request [here](https://github.com/DigitecGalaxus/next-yak)

## Troubleshooting

### I get a compile time error in my app router page

This is a known issue with Webpack when styles are used in files that also use the [metadata API](https://nextjs.org/docs/app/building-your-application/optimizing/metadata) of Next.js. See the [open Next.js issue](https://github.com/vercel/next.js/issues/67591) for details.

If you are using Webpack, switching to Turbopack resolves this issue. With Turbopack enabled, styled components and the metadata API work together without problems.

If it's not this issue, please read the error carefully as it should indicate how to fix the problem.

### My styled components don't show up in React DevTools

yak optimizes your JSX at build time by inlining a styled component directly into the place where it is used:

```tsx
const Button = styled.button`
  color: red;
`;

const App = () => <Button type="submit">Save</Button>;

// compiles to
const App = () => (
  <button type="submit" className="Button_c1d2e3">
    Save
  </button>
);
```

This skips a component and its rendering work for every element. Your styles are unaffected, but `<Button>` is gone from the React tree, so it no longer appears in React DevTools or in component stacks. It also disappears in development, so that development and production behave the same, and for the same reason `displayNames` has no effect on an inlined usage.

This is folding, controlled by the `foldStatic` option, which also folds a static `css` prop into a plain `className`. See [Folding](/docs/folding) for what folds, how to turn it off, and the rest of the caveats.

### My styles are not applied

If your styles are not applied, the first thing you should check is the transformed output of your component.
To do that, enable the `debug` option in the `withYak` function.

<Tabs title="Next.js config" items={['next.config.ts', 'next.config.js', 'next.config.mjs']}>
<Tab value="next.config.ts">
```ts
export default withYak(
  {
    // Enable for all files
    debug: true,

    // Or filter by regex pattern:
    // debug: { pattern: "myPage" },

    // Or filter by output type only:
    // debug: { types: ["css"] },

    // Or combine pattern + types:
    // debug: { pattern: "Button", types: ["css", "css-resolved"] },
  },
  nextConfig,
);
```
</Tab>

It could be a specificity issue, a wrong selector, or a wrong usage of the library and if you don't know why your styles are not applied, feel free to [open an issue](https://github.com/DigitecGalaxus/next-yak/issues/new/choose).
