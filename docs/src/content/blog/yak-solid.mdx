With `@yak/solid`, you write your CSS right next to your Solid components, in template literals,
with props for the parts that change. At build time, yak moves that CSS into real stylesheets. In
the browser, only class names and a few CSS variables are left, and your signals drive them.

```tsx
import { createSignal } from "solid-js";
import { styled, css } from "@yak/solid";

const Hand = styled.div<{ $angle: number }>`
  background: #009688;
  transform: rotate(${(props) => props.$angle}deg);
`;

const Button = styled.button<{ $primary?: boolean }>`
  color: #009688;
  ${(props) =>
    props.$primary &&
    css`
      background: #009688;
      color: white;
    `}
`;

export default function Clock() {
  const [angle, setAngle] = createSignal(0);
  return (
    <>
      <Hand $angle={angle()} />
      <Button $primary onClick={() => setAngle(angle() + 30)}>
        Tick
      </Button>
    </>
  );
}
```

## What yak does

yak is a CSS-in-JS library that does its work at build time. A compiler, written in Rust as an
SWC plugin, reads your styled components while Vite builds the app:

- The CSS becomes a real stylesheet with generated class names. Vite bundles it like any other
  CSS file, so the browser downloads and caches it as CSS, not as JavaScript.
- The component keeps only what it needs at runtime: the class names, and one CSS variable for
  each dynamic value, like `$angle` above. Nothing injects or parses CSS in the browser.

yak started for React and Next.js, and it runs in production at
[Digitec Galaxus](https://www.galaxus.ch), the largest online shop in Switzerland.
`@yak/solid` uses the same compiler. Only the small runtime on top is new, and it is written for
Solid.

## Built for components that run once

A Solid component runs once, so there is no re-render that could compute the styles again. A styled-components runtime that copies its props at that moment freezes them, and
your button never turns primary.

`@yak/solid` never copies props. Each styled component does its work in one memo:

- A static `styled.div` becomes a plain CSS class and a single `class` binding.
- A dynamic value like `${(props) => props.$angle}` becomes a CSS variable on the element's inline
  `style`. When the signal changes, only the `class` and `style` bindings update. The element
  stays.
- Reads inside your CSS are tracked like any other read in Solid. If the CSS never reads
  `props.theme()`, the component never subscribes to the theme.

## Built with help from Ryan Carniato

We built `@yak/solid` on the Solid 2 release candidates, and Ryan Carniato helped us the whole
way. He fixed the compiler issues we ran into, for hot reload
([#3090](https://github.com/solidjs/solid/issues/3090)) and for invalid HTML
([#3099](https://github.com/solidjs/solid/issues/3099)).

We also spent a lot of time on speed. A rewrite of the runtime
([#644](https://github.com/galaxuslabs/yak/pull/644)) made server rendering 6.6 times
faster. Ryan then used yak as a [benchmark for Solid itself](https://github.com/solidjs/solid/issues/3389),
made Solid's own primitives as fast as our hand-written code, and sent us
[a pull request](https://github.com/galaxuslabs/yak/pull/659) so that `@yak/solid` uses
them. Thank you, Ryan!

## If you know styled-components

The API follows styled-components: `styled.tag`, `styled(Component)`, `css`, `keyframes`,
`.attrs()`, transient `$` props that never reach the DOM, and a `css` prop on every element. A few
things are shaped by Solid:

- `useTheme()` returns an accessor, like a signal. Read `theme().highContrast`, and
  `props.theme()` inside your CSS. Reading it subscribes to theme changes.
- Use `class` instead of `className`, also inside `.attrs({ ... })`.
- Solid compiles JSX itself, so the `css` prop types work as soon as you import `@yak/solid`.

## Status

`@yak/solid` is experimental, because Solid 2 is still a release candidate. We track it closely,
and breaking changes are possible until Solid 2 is stable. It needs `solid-js` and `@solidjs/web`
2.0.0-rc.15 or newer, so Solid 1 is not supported.

## Try it

Install the package and the Solid 2 Vite plugin:

```bash
npm install @yak/solid
npm install -D @solidjs/vite-plugin@next
```

Add the yak plugin before `solid()`:

```ts title="vite.config.ts"
import { defineConfig } from "vite";
import solid from "@solidjs/vite-plugin";
import { yak } from "@yak/solid/vite";

export default defineConfig({
  plugins: [yak(), solid()],
});
```

The [Solid guide](/docs/solid) covers setup, theming, the `css` prop and SolidStart. The
[`@yak/solid` README](https://github.com/galaxuslabs/yak/tree/main/packages/yak-solid) has the same, and
[`examples/vite-solid`](https://github.com/galaxuslabs/yak/tree/main/examples/vite-solid)
is a full app.
